# 漫画修复实验室 · manga-relab

**项目目的：用最高的效率，把私藏的扫图资源修成易于收藏的格式。**

这是一个跑在浏览器里的节点式修图工作台，专门用来修扫描的漫画和书页：修复网点、去装订阴影、锐化、调曲线，然后整个文件夹批量处理。

## 先叠甲

1. 汉化组的存在有时代特殊性，当下已经不是大航海时代。本项目仅支持用于处理自用收藏的资源，有些东西私下享受就好了。**不要传播盗版，不要做让作者伤心的事！**
2. 本项目为单页纯前端应用，部署在网页端仅仅是为了方便访问。所有图片和数据都只在你自己的电脑上处理，不会上传到任何地方，也支持完全离线运行。

## 序言

主包是一名汉化组老兵，十多年前曾经绞尽脑汁研究怎么把扫描的漫画修得好看。但 PS 自带的滤镜满足不了扫描件的修复，各种插件又往往是为摄影等场景设计的，要花大量精力调整和适应才能拿来修印刷件。工具不趁手，就只能用复杂的流程来凑，动辄录制几十个步骤的动作，处理一张图片光跑动作可能就要几十分钟，实在是过于折磨。

后来编程能力提高了，主包也想过写个自动化程序来做这件事。但主包有的只是修图本身的技术，而一个能用、有一定扩展性的修图软件，打磨 UI、搭 API 基建这些纯事务性的工作，并不是个人非全职开发者能承受的。

直到有了 AI agent，主包终于可以把 UI、状态管理这些杂活交给 AI，自己专注打磨最快最好的修图流水线了。

选纯前端 WebUI，是因为它开发快、调试快、打包快。有了 WebGPU，既能调用 GPU，又不用花时间纠结跨平台适配，能在任何设备上运行。性能虽然比不上原生的 GPU 编程，但还是比当初那些纯 CPU 运行的修复网点插件强多了。

所以，不要嘲笑这个单页纯前端应用像 AI 泔水，它是主包充分考虑后的选择，是基于热爱诞生的。

> 注：AI 泔水指用 AI 洗稿已有项目，做出一个自己都不会看第二眼、也不会长期维护的东西。

顺嘴提一句：虽然做成了一个看起来挺全乎的管线编辑 WebUI，但它本质上依然只是主包给私藏资源修图的工作流包装盒。

## 运行要求

- **浏览器**：桌面版 Chrome 或 Edge。Firefox 和 Safari 不支持读写本地文件夹，用不了。
- **显卡**：需要开启浏览器的硬件加速，并支持 WebGPU。没有 WebGPU 时只有降噪能用 CPU 跑，其他 GPU 滤镜无法使用。
- **访问方式**：要么打开在线地址，要么本地启动。直接双击 `index.html` 只能看界面，没法读写图片。

### 在线使用

打开 <https://manga-relab.tohsakarat.icu> 即可。

### 离线 / 本地运行

下载本仓库，在目录中运行：

```bash
python -m http.server 8765
```

然后在浏览器中打开 <http://localhost:8765>。不需要安装任何依赖。

> 注意：数据按访问地址分开保存，**换了端口或者换了网址，看到的就是一份全新的空数据**。

### 构建发布版本

构建需要 Node.js 20.19 或更新版本。首次安装构建依赖，然后生成发布文件：

```bash
npm ci
npm run build
```

产物位于 `dist/`，可直接部署整个目录，也可本地启动：

```bash
python -m http.server 8765 --directory dist
```

构建按 `index.html` 的加载顺序合并脚本，将第三方库和应用分别打包，合并并压缩 CSS；JS 做常规压缩和表达式优化，关闭变量名混淆。两个脚本使用 `defer` 加载，资源文件名包含内容哈希，更新后使用新地址。滤镜及 GPU 批次辅助函数保留原始源码，因为参数表解析、Worker 执行和“编辑脚本”依赖函数源码。预装流水线自动扫描 `src/pipelines/` 下全部 `.json` 并内置到应用脚本。第三方许可证随产物保留。构建不改动源文件，每次重新生成 `dist/`；源码直接运行仍不需要安装依赖。

Cloudflare Pages 的发布配置与手动部署命令见 [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md)。正式部署需先由项目负责人确认。

### 持续调试

```bash
npm run dev
```

首次构建后启动 `http://localhost:8765`，提供 `dist/` 的文件并禁用开发服务缓存。修改源码、样式、第三方库、构建脚本或预装流水线 JSON 后自动重新构建；构建完成后手动刷新浏览器查看更新。构建失败会显示错误，修改后继续构建。按 Ctrl+C 停止服务及监听。

只需要自动构建时运行 `npm run watch`。开发服务的端口可通过 `PORT` 环境变量设置；换端口会使用另一份浏览器本地数据。WSL 的 Windows 挂载盘使用轮询监听，以捕获 Windows 编辑器保存的变更。

## 界面介绍

### 第一屏：首页

顶部 GitHub 图标及仓库地址链接到本项目的公有仓库，在新标签页打开；窄屏保留图标。

<!-- TODO：首页截图 -->

面板一共分三个部分，中间的分隔条可以拖动调整宽度。

**左侧：资源面板。** 在这里新建图片集，添加图片或者导入整个文件夹（会包含子文件夹）。拖动卡片可以调整处理顺序；移除图片只是从列表里去掉，不会删除文件。

提醒一下，因为网页端的权限限制，预览和处理图片前都需要在弹窗里授权文件夹，**刷新页面后也要重新授权一次**。工具会自动弹出目录选择器引导你。最好把同一批图片放在同一个文件夹下，这样授权一次就够了。

**中间：流水线列表。** 流水线就是处理图片的管线，我们在下面的编辑器里细说。可以新建、复制、导入和导出 JSON。首次使用当前站点时，会自动为每条预装流水线创建一份副本。点“引入预装的流水线”可以再创建一整套副本，留在首页供编辑。目前预装“标准修复流水线”：输入 → 降噪 → 去阴影 → USM 锐化 → 曲线 → 输出。刷新或删空列表不会重复自动创建。

提醒一下，任务跑到一半时，如果改了流水线、改了参数或者调整了图片顺序，需要清空进度重新执行。正在运行的任务用的是开始时的流水线，中途修改不会影响它。

**右侧：任务列表。** 选好图片集和流水线，为流水线设置好参数，设置输出位置后就可以开始。可以观察处理进度，也可以随时暂停（等当前这张处理完才会停）和继续。刷新页面后进度会保留。清空进度不会删除已经输出的文件。

### 第二屏：流水线编辑器

<!-- TODO：编辑器截图 -->

这是一个滤镜节点编辑器，如果你用过 Unity、Blender，一定不会陌生。

把输入连接到各种滤镜节点，经过一系列串行或并行合成的处理，最终抵达输出。

**基本操作**

| 操作 | 方式 |
| --- | --- |
| 添加节点 | 画布上右键 |
| 连线 | 从端口拖到另一个端口，一个输出可以连到多个节点 |
| 调参数 | 单击节点，打开参数窗口，左边参数右边预览 |
| 移动节点 | 拖动节点标题栏 |
| 框选 | 在空白处拖动 |
| 平移画布 | 中键拖动，或按住空格拖动 |
| 缩放画布 | 滚轮（在节点预览图上滚动则是缩放图片） |
| 删除 | Delete |
| 全选 / 复制 / 粘贴 / 复制一份 | Ctrl+A / Ctrl+C / Ctrl+V / Ctrl+D |
| 导出流水线 | Ctrl+E |

**实时预览。** 在右侧选一张预览图，勾选“编辑器预览”，每个节点下方都会显示同一块区域的处理结果。改参数或脚本只重算受影响节点和沿输出连线连接的下游，上游及无关分支保留缓存；改连线从接收节点开始更新。移动节点、改名不重算图片，开关参数窗口也会保留画布缓存。在预览图上拖动可以移动观察位置，滚轮可以缩放；换图片或观察区域后重新计算对应区域。预览只处理你看到的那一小块；图片边缘和去阴影这类需要看整页的滤镜，预览可能和最终结果略有差异，以整图处理为准。

**试跑。** 预览图下方的“试跑”会把这张图完整处理一遍，并把结果下载下来，不会改动原图。

普通预览先显示接到输出的分支，再计算没接输出的草稿分支，避免慢草稿拖住输出结果。浮窗只计算当前节点及其必要上游。

画布节点和参数面板的预览视窗在对应节点计算时，上沿显示 3 像素细进度条，按节点实际进度更新；完成、取消或失败后隐藏。

**把参数交给任务。** 点节点参数旁边的链接按钮，这个参数就会出现在输入节点上，之后在任务里就能单独修改它，不影响流水线本身的默认值。

### 自带滤镜

主包集成了修扫描件的常用节点：

| 滤镜 | 说明 |
| --- | --- |
| 降噪 | 修复印刷网点的核心滤镜，搜索半径要覆盖网点的周期 |
| 去阴影 | 检测并去除书页装订处的阴影，尺度按页面宽度的百分比设置 |
| USM 锐化 | 数量、半径、阈值 |
| 曲线 | 拖动编辑的色调曲线，也可以直接输入数值 |
| 表面模糊 | 半径 1–100 像素、阈值 2–255 色阶；默认半径 5、阈值 15，平滑相近色阶并保留边缘 |
| 最大值 / 最小值 | 可选方形或圆度 |
| 查找边缘 | 无参数 |
| 缩图 | 按百分比或像素设置尺寸，可锁定比例 |
| 合成 | 多条图像输入按槽位顺序叠放，支持常用混合模式 |
| 偏移 | 按像素或百分比移动图片，支持正负水平、垂直偏移 |
| 自定义脚本 | 自己写滤镜，或者在自带滤镜的源码基础上修改 |

都是很经典的滤镜，就不赘述了。参数形式参照 PS，但算法是本项目自己实现的，结果不保证和 PS 逐像素一致。

旧流水线中的高斯模糊节点自动改为表面模糊，保留连线，半径取整到 1–100 并补上阈值 15。已有任务进度需清空后重新执行。

偏移节点的百分比分别按上游图片宽、高计算，取整到像素；切换单位沿用输入数字。正值向右、向下移动并扩展透明画布，负值越过左上原点的部分裁切。偏移支持局部预览、参数暴露和任务参数覆盖。

### 输出

输出节点有两种保存方式：

- **原地保存**：直接覆盖原文件，保留原格式和文件名。**会覆盖原图，请务必先备份！**
- **保存到目录**：可选 PNG（无损）、JPG、WebP，JPG 和 WebP 可以调质量。文件名沿用原图，重名文件默认覆盖，也可选择给新文件增加 `_1`、`_2` 等后缀。

两种方式都可以选择 RGB、灰度、索引颜色（2–7 位，最多 4–128 色）。

## 数据保存

- 图片集、流水线、参数和任务进度都保存在浏览器本地。清除浏览器数据会一起清掉，**重要的流水线记得导出 JSON 备份**。
- 图片文件本身不会被复制或上传，工具只记录它们的位置，所以刷新后需要重新授权。

## 二次开发

所有滤镜都是单个脚本文件，编辑器也接受用户自己写的修图脚本。主包想现在应该没人会手写脚本了，所以就不写教程了。有二次开发需求的话，请让各家 agent 自己去爬仓库，接口说明在 [`AGENTS.md`](AGENTS.md) 里。

目录按职责划分：

```text
src/
  app.js       应用入口
  core/        流水线图、执行引擎、滤镜注册与预览采样
  filters/     自带滤镜与计算实现
  pipelines/   流水线编辑器直接导出的预装 JSON 文件
  state/       业务定义与编辑器状态
  io/          文件授权、读写与输出编码
  ui/          首页、节点编辑器与共用控件
styles/        页面样式
docs/          规格文档
tests/         CPU 降噪对照测试
vendor/        本地第三方库及许可证
scripts/       发布构建与预装流水线生成脚本
dist/          npm run build 生成的发布文件
```

详细文件结构见 [`docs/SPEC.md`](docs/SPEC.md)。静态服务仍从项目根目录启动，脚本加载顺序由 `index.html` 维护。新增预装流水线时，将编辑器导出的 `.json` 原样放入 `src/pipelines/`，文件名自行选择。发布构建自动扫描全部 JSON 并内置，无需修改文件清单。直接运行源码时，新增或修改 JSON 后运行 `npm run build:pipelines` 更新内置快照；该命令仅需 Node.js，不需安装依赖。生成的 `src/core/preinstalled-pipelines.js` 不手动编辑。CPU 降噪对照测试可手动运行 `node tests/test.cjs`。
