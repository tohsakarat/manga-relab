## 0. 总体架构

将现有"线性 Tab 切换"单图处理界面推倒重构为 **ComfyUI 风格节点编辑器 + 批处理任务管理** 的两层 UI。

- **第一层**：入口主界面，三栏并列——图片集管理、流水线管理、任务管理。
- **第二层**：流水线编辑器，无限画布节点编辑器 + 右侧固定信息侧栏。
- 两层之间通过顶部导航栏切换，第二层带有"返回入口"按钮和当前编辑流水线名称显示。

### 持久化策略

- **localStorage 存储**：图片集定义、流水线定义（含所有节点/连线/参数/位置）、任务定义（含进度状态）。
- **不存入 localStorage**：图片文件本身（File 对象在运行时由用户选入）。编辑器所选预览图片的副本单独存入 IndexedDB。图片集来源位置句柄保存在 `screenlab-assets` IndexedDB，用于目录选择器定位；输出目录句柄只保留在内存。
- 业务定义使用顶层 key `screenlab-v2`，值为 JSON 对象，包含 `imageSets`、`pipelines`、`tasks` 三个子对象。编辑器预览设置另用 `screenlab-editor`，按流水线 ID 对应，不进入流水线定义。
- 每次修改后自动保存，无需手动保存按钮。

### 技术约束

- 纯前端，无业务后端。推荐在固定 localhost 端口运行静态服务，再用 Chrome / Edge 打开；直接打开 HTML 可以加载界面，文件写入能力取决于浏览器实际提供的接口。
- `src/filters/gpu.js`、`src/filters/spine.js`、`src/filters/sharpen.js`、`src/filters/tone.js`、`src/filters/algorithm.js` 保持现有算法。`src/ui/curve.js` 改为可挂载到容器的控件；`src/core/filters.js` 增加可选运行时注册 ID，保证同名脚本的不同版本不会被错误复用。
- 现有的 `ScreenFilters.register()`、`ScreenFilters.start()`、`ScreenFilters.defaults()` 等 API 继续使用，新 UI 层调用它们来执行滤镜。

## 1. 第一层：入口主界面

### 1.0 布局

三栏水平并列，撑满视口高度。每栏有自己的标题和工具按钮。

### 1.1 左栏：图片集管理

#### 1.1.1 数据结构

```jsonc
// localStorage 中 imageSets 的结构
{
  "imageSets": {
    "set-uuid-1": {
      "id": "set-uuid-1",
      "name": "第一卷扫描",
      "createdAt": 1697000000000,
      "files": [
        // id 稳定标识引用；path 为所选目录下相对路径，普通多选为文件名
        { "id": "file-uuid-1", "path": "第一卷/page001.png", "name": "page001.png", "size": 2048000, "type": "image/png", "lastModified": 1697000000000 },
        { "id": "file-uuid-2", "path": "第一卷/page002.png", "name": "page002.png", "size": 1920000, "type": "image/png", "lastModified": 1697000000000 }
      ]
    }
  }
}
```

`files` 数组只存路径及文件元数据，不存内容。浏览器选择器不会向网页提供可任意读取的系统绝对路径，不能将文本路径当作授权。当前页面内通过文件句柄或 File 对象读取；刷新后选择来源目录重新授权，以相对路径关联原条目，旧版没有目录前缀的条目按文件名和大小关联。原地保存要求可写句柄。

#### 1.1.2 UI 元素

- **顶部**：栏标题"图片集"+ 右侧"＋ 新建"按钮。
- **列表区域**：纵向排列所有图片集卡片，每张卡片显示：
  - 图片集名称（可双击进入重命名编辑状态，回车或失焦确认）。
  - 文件数量（如"12 张"）。
  - 右侧操作按钮：删除（弹确认）。
- **点击卡片**展开该图片集，显示：
  - 双列图片卡片，每项显示完整图片缩略图、文件名、大小及授权状态，右上角有"×"按钮可移除单个文件；完整相对路径显示在悬停提示中。缩略图按浏览器懒加载，未授权时显示“待授权”，重新授权后恢复预览。
  - 底部"＋ 添加文件"按钮，点击弹出文件选择器（`accept="image/*"` + `multiple`），选入后将图片卡片追加到列表。
  - 底部"清空"按钮，清空该图片集的所有文件条目。
- 同一时刻只展开一个图片集（手风琴模式）。
- 点击展开时，若图片集存在未授权的文件且没有任务正在使用它，自动弹出目录选择器；“重新授权”及任务准备阶段也统一选择目录。按当前图片集中未授权图片的直属目录统计数量，以数量最多的目录句柄作为选择器 `startIn`；原来以文件选择器导入的条目可用保存的文件句柄定位到父目录。旧版没有保存位置句柄的记录首次需要手动选择目录。
- 目录选择完成后扫描其全部图片及子目录，更新原条目的文件来源及元数据，新图片追加到末尾，保留原条目 ID 和用户排序。保存每个扫描目录的位置句柄，以便刷新后定位；选择已知子目录时沿用原相对路径前缀，避免重复导入。新增图片或文件内容变化后，首页重置引用该图片集的未运行任务进度；任务准备阶段发现这类变化且已有进度时提示清空后重新开始。
- 取消后保留“待授权”占位，可通过“重新授权”按钮重试。常规界面重绘不会弹出选择器。

#### 1.1.3 交互细节

- 新建图片集时自动生成名称"未命名图片集"并立即进入重命名编辑状态。
- 删除图片集时，如果有任务正在引用它，弹出警告"有 N 个任务正在使用此图片集，删除后这些任务将无法运行。确认删除？"。
- 图片卡片按从左到右、从上到下的顺序排列，支持拖拽排序（决定批处理时的处理顺序）。

### 1.2 中栏：流水线管理

#### 1.2.1 数据结构

```jsonc
{
  "pipelines": {
    "pipe-uuid-1": {
      "id": "pipe-uuid-1",
      "name": "标准修复流水线",
      "createdAt": 1697000000000,
      "updatedAt": 1697100000000,
      // nodes、edges、exposedVars 等完整定义见第二层规格
      "graph": { /* 见 §2 */ }
    }
  }
}
```

#### 1.2.2 UI 元素

- **顶部**：栏标题"流水线"，右侧依次为“批量导出流水线”、导入和"＋ 新建"图标按钮。批量导出按列表顺序分别下载所有流水线的独立 `.json` 文件，复用单条导出的格式与文件名；列表为空时禁用。
- **列表区域**：纵向排列所有流水线卡片，每张卡片显示：
  - 流水线名称（单击进入重命名，回车或失焦保存，Esc 取消）。
  - 节点数量摘要（如"5 个节点"）。
  - 最后编辑时间。
  - 操作按钮（横排图标）：
    - **编辑**：进入第二层流水线编辑器。
    - **复制**：创建一份副本，名称自动加" (副本)"后缀。
    - **导出**：将流水线定义导出为 `.json` 文件下载。
    - **删除**：弹确认，如果有任务引用则警告。
- **导入按钮**：栏底部或标题栏旁边放一个"导入流水线"按钮，接受 `.json` 文件，解析后添加到列表。

#### 1.2.3 流水线导入导出格式

导出的 JSON 文件包含完整的 `graph` 对象（节点、连线、参数、位置），以及流水线名称、版本号。导入时校验格式，如果引用了系统中不存在的滤镜 ID 则提示用户。

```jsonc
{
  "format": "screenlab-pipeline",
  "version": 1,
  "name": "标准修复流水线",
  "graph": { /* 完整图定义 */ }
}
```

#### 1.2.4 新建流水线

新建时自动创建一个包含 1 个输入节点和 1 个输出节点（默认"原地保存"模式）的空流水线，输入节点位于画布左侧中央，输出节点位于右侧中央，两者之间无连线。名称默认"未命名流水线"并立即进入重命名状态。

中栏同时提供“引入预装的流水线”操作，为每条内置流水线创建一份独立副本并留在首页。`src/pipelines/` 保存编辑器直接导出的独立 JSON 文件，完整保留 `format / version / name / graph` 结构；新增模板直接将导出文件放入目录，文件名自行选择。`scripts/build-pipelines.mjs` 自动扫描目录全部 `.json` 并嵌入脚本，无需登记具体文件名。发布构建直接生成最新内置数据，不改动源码；直接运行源码前，用 `npm run build:pipelines` 更新 `src/core/preinstalled-pipelines.js` 内置快照，该命令仅需 Node.js，不需构建依赖。生成文件不手动编辑。副本通过 `Graph.importDefinition` 复制和规范化图，使用独立的流水线 ID。首次启动当前站点（尚无 `screenlab-v2` 保存数据）时自动创建全部副本，刷新或删空已有列表不会重复创建；已有保存数据的用户可点击按钮引入。

现有“标准修复流水线”使用用户导出的定义：输入 → 降噪 → 去阴影 → USM 锐化 → 曲线 → 输出，保留节点位置及画布视图。降噪的 3 个参数、去阴影的 3 个参数、曲线点通过 7 条参数连线暴露到输入节点，执行时以暴露变量的默认值为准。降噪默认图块半径 3、搜索半径 8、匹配容差 80；去阴影尺度 13.6%、强度 100%、位置不指定；锐化数量 100%、半径 10%、阈值 0；曲线点为 (0,0)、(119,0)、(241,255)、(255,255)。该模板默认使用目录输出，需要用户选择目录。

### 1.3 右栏：任务管理

#### 1.3.1 数据结构

```jsonc
{
  "tasks": {
    "task-uuid-1": {
      "id": "task-uuid-1",
      "name": "第一卷标准修复",
      "createdAt": 1697000000000,
      "imageSetId": "set-uuid-1",      // 引用的图片集
      "pipelineId": "pipe-uuid-1",     // 引用的流水线
      "params": {                       // 流水线暴露变量的用户填写值
        "var-uuid-a": 25,              // key 是变量 ID，value 是用户填的值
        "var-uuid-b": "center"
      },
      "status": "idle",                // idle | running | paused | completed | error
      "progress": {
        "current": 0,                  // 已处理图片数
        "total": 12,                   // 总图片数
        "currentFileName": ""          // 当前正在处理的文件名
      }
    }
  }
}
```

#### 1.3.2 UI 元素

- **顶部**：栏标题"任务"+ 右侧“顺序执行”和"＋ 新建"按钮。顺序执行按点击时的列表顺序逐个运行未完成任务，已有进度从下一张继续；无法启动的任务提示原因后继续下一项。暂停当前任务同时停止后续任务。顺序执行期间不能手动启动其他任务，期间新建的任务留到下次执行；已有任务正在运行或准备时禁用顺序执行按钮。
- **列表区域**：纵向排列所有任务卡片。

**收起状态**（默认）每张卡片显示：
- 任务名称。
- 状态标签（空闲 / 运行中 / 已暂停 / 已完成 / 出错），用不同颜色区分。
- 进度条（如果已开始过）+ 文字"3 / 12"。
- 右侧展开箭头。

**展开状态**额外显示：
- **图片集选择器**：下拉框，列出所有已有图片集，可切换。切换后 `progress` 重置。
- **流水线选择器**：下拉框，列出所有已有流水线，可切换。切换后 `params` 重置为新流水线的默认值，`progress` 重置。
- **参数编辑区**：列出当前流水线暴露的所有变量，每个变量显示为 `节点名.参数名 = [输入控件]`。输入控件的类型根据变量的参数定义决定：
  - `integer` / `number`：数字输入框，带 min/max/step。
  - `enum`：下拉选择框。
  - `boolean`：复选框。
  - `json`：文本输入框。
  - `directory`：文件夹选择器，显示目录名称及授权状态。
  - 其他：文本输入框。
- **操作按钮**（底部横排）：
  - **开始** / **继续**（根据状态切换文字）：开始或从暂停处继续执行。图片尚未授权时，点击后弹出来源目录选择器，然后开始处理。
  - **暂停**：暂停当前处理（完成当前图片后停下，不中途打断滤镜执行）。
  - **清空进度**：将 progress 重置为 0，状态回到 idle。
  - **重命名**：进入名称编辑状态。
  - **删除**：弹确认后删除任务。

#### 1.3.3 任务执行流程

1. 用户点击"开始"。
2. 如果图片集文件尚未在内存中，弹出目录选择器，优先定位到当前图片集中未授权图片最多的目录，重新授权并纳入该目录及子目录的全部图片。未匹配到完整图片集时提示继续选择其他来源目录，任务不消耗进度、不默默跳过缺失资产。图片集发生变化且任务已有进度时，需要清空进度后重新开始。
3. 按图片集中文件的排列顺序，依次对每张图片执行流水线：
   a. 将图片解码为 ImageData。
   b. 按流水线的拓扑排序，依次执行每个节点的滤镜（调用 `ScreenFilters.start()`）。
   c. 每个节点执行完后，将输出传给下游节点作为输入。
   d. 到达输出节点时，按输出节点的设置保存结果。
4. 处理完一张后更新进度，开始下一张。
5. 全部完成后状态变为 `completed`。

#### 1.3.4 暂停与继续

- 暂停时：等当前正在处理的那张图片完成（不会中途打断一个滤镜的 Worker 执行），然后停下来，记录 `progress.current`。
- 继续时：从 `progress.current` 开始处理下一张图片。如果文件已经不在内存中（比如用户刷新了页面），需要重新选入文件。

#### 1.3.5 输出保存

输出模式必须符合其名称，不用自动下载替代文件写入。
- **原地保存**：对导入时获得的原文件句柄请求 readwrite 权限，调用 createWritable 写回原文件，保留原编码及文件名，不提供压缩设置。没有句柄或没有权限时提示授权问题，不执行伪覆盖。同一任务最多有一个原地保存输出，其他分支用目录输出。
- **指定目录保存**：由用户通过 showDirectoryPicker 授权目录，再获取目标文件句柄写入。保留原文件名主体，按所选格式使用 `.png`、`.jpg`、`.webp` 扩展名；重名文件可选择覆盖（默认）或给新文件增加后缀，后者按 `_1`、`_2` 递增找到可用名称。旧流水线未设置此项时默认覆盖，选择随流水线持久化、复制及导入导出。
- 目录可在流水线输出节点里选择，也可在任务中单独选择，任务所选目录优先。输出目录可作为 `directory` 参数暴露到输入节点；已连接时使用该变量的任务覆盖值或默认值，任务中不再显示独立的输出目录按钮。参数值为 `{ key, name }`，只保存运行时句柄引用键和显示名称，句柄只在内存；刷新或导入后重新授权。
- 两种输出方式均提供 RGB、黑白（灰度）、索引颜色。目录保存提供无损（PNG）、JPG、WebP；JPG、WebP 的质量范围为 1–100%，默认 95%。原地保存支持 PNG、JPEG、WebP 原图，其他编码格式报告失败。
- 索引颜色只支持 PNG，位数为 2、3、4、5、6、7，限制调色板最多 4、8、16、32、64、128 色，默认 7 位；PNG 文件按实际颜色数使用合法的索引存储位深。原地保存索引颜色要求原图为 PNG。
- 默认颜色模式为 RGB，目录输出默认为 PNG。颜色转换属于输出编码，不进入滤镜及局部预览。灰度 PNG 使用灰度通道并保留透明度；JPEG、WebP 使用浏览器编码灰阶 RGB 像素。

## 2. 第二层：流水线编辑器

### 2.0 进入与退出

- 从第一层中栏点击某个流水线的"编辑"按钮后，整个界面切换到第二层。
- 第二层顶部有一个简洁的导航栏：
  - 左侧："← 返回"按钮，点击回到第一层。
  - 中间：当前流水线名称（单击进入重命名，回车或失焦保存，Esc 取消）。
  - 右侧：合法性状态指示器（绿色"✓ 合法" / 红色"✗ 不合法 — 原因说明"）。

### 2.1 画布

#### 2.1.1 无限画布基础

- 整个第二层的主区域是一个无限画布，使用 `<canvas>` 或 DOM 元素 + CSS transform 实现。
- **推荐实现方式**：使用一个容器 div，内部所有节点是绝对定位的 DOM 元素，容器整体通过 CSS `transform: translate(panX, panY) scale(zoom)` 实现平移和缩放。这样节点内的 HTML 控件（输入框、下拉框等）可以原生交互，不需要在 canvas 上模拟表单控件。
- 画布背景绘制点阵网格（浅色小点，间距 20px，随缩放级别变化），帮助用户感知位移和缩放。

#### 2.1.2 画布交互

- **平移**：

### 2.2 节点

#### 2.2.1 节点通用外观

每个节点是一个圆角矩形卡片，包含：

```
┌──────────────────────────────┐
│  [类型图标] 节点名称          │  ← 标题栏，背景色按类型区分
├──────────────────────────────┤
│                              │
│  ● 输入端口名称         ○    │  ← 左侧是输入端口，右侧是输出端口
│  ● 输入端口名称         ○    │     ● 实心圆 = 输入端口
│                         ○    │     ○ 空心圆 = 输出端口
│                              │
├──────────────────────────────┤  ← 只在"编辑器预览"开启时显示
│  [缩略预览图 ≤500×500]       │
└──────────────────────────────┘
```

- **标题栏颜色**按节点类型区分（方便视觉辨认）：
  - 输入节点：蓝色系 `#3b82f6`
  - 输出节点：绿色系 `#22c55e`
  - 降噪：橙色系 `#f59e0b`
  - 去阴影：紫色系 `#a855f7`
  - USM 锐化：红色系 `#ef4444`
  - 曲线：青色系 `#06b6d4`
  - 自定义脚本：灰色系 `#6b7280`
- **选中状态**：节点边框变为高亮色（`--accent`），外加一圈淡色光晕。
- **非法状态**：如果节点未连线（处于断路状态），标题栏右上角显示一个黄色警告三角图标。
- **节点最小宽度**：200px。高度随内容自适应。

#### 2.2.2 输入端口与输出端口

- 每个端口是一个小圆圈（直径 12px），定位在节点卡片的左侧（输入端口）或右侧（输出端口）边缘。
- 端口颜色按数据类型区分：
  - **图像数据**（ImageData）：黄色 `#eab308`
  - **参数值**（暴露变量的连线）：蓝色 `#3b82f6`
- 鼠标悬停在端口上时，端口放大到 16px 并显示 tooltip（端口名称 + 数据类型）。

#### 2.2.3 端口定义（按节点类型）

**输入节点**：
- 输出端口：`image`（图像数据，来自图片集的当前图片）
- 输出端口：每个暴露的变量各一个（参数值类型）
- 无输入端口。
- 卡片内容区显示所有已暴露变量的列表，每个变量显示 `显示名 = 默认值`。
- 画布卡片中的整条入参行可拖动排序，右侧圆形端口仍用于连线，单击入参行打开参数浮窗；浮窗中的入参通过左侧拖动手柄排序。按目标项的上半部或下半部插入到其前方或后方。顺序直接保存在 `graph.exposedVars` 数组中，任务参数列表沿用该顺序，随流水线保存、复制和导入导出；排序不改变参数值、变量 ID 或连线，不使图像缓存失效。

**输出节点**：
- 图像输入行下方、保存方式上方显示“预估大小：约 … KB/MB”。复用输出编码器编码当前局部输出预览，按其整图面积与预览面积的比例推算；目录保存使用所选格式、质量和颜色模式，原地保存使用预览文件 MIME 类型及现有覆盖编码质量。没有图片或输出预览时显示对应等待状态，编码失败显示“无法估算”并在悬停提示中提供原因。估算随预览结果和编码设置更新，只保留在当前编辑器内存中，不写文件，不额外执行整图滤镜；实际大小可能不同。
- 输入端口：`image`（图像数据）
- 输入端口：`directory`（输出目录），可拖到输入节点或通过参数浮窗的链接按钮暴露；多个输出节点可共用同一目录变量。端口在两种保存模式下都保留，目录选择控件仅在指定目录模式显示。
- 无输出端口。
- 卡片内容区和参数浮窗共用保存设置：输出模式选择器（"原地保存" / "指定目录保存"）、颜色模式、索引位数；目录模式另显示重名文件处理（"覆盖（默认）" / "给新文件增加后缀"）、压缩方式、有损质量及选择目录按钮。索引颜色锁定 PNG。缺少写入 API 时明确报告无法写入。

**降噪节点（denoise）**：
- 输入端口：`image`
- 输出端口：`image`
- 参数：`patch`（图块半径, int, 2~8, 默认4）、`search`（搜索半径, int, 4~24, 默认12）、`strength`（匹配容差, num, 5~80, 默认25）
- 直接使用修复结果，等同于原“修复混合”100%。已保存及导入的自带降噪节点移除旧 `blend` 值及对应参数连线；不再使用的自动暴露变量及其任务覆盖值一并移除。仍连接其他参数的共享变量保留，自定义脚本副本保持原源码。

**去阴影节点（spine）**：
- 输入端口：`image`
- 输出端口：`image`
- 参数：`scalePercent`（阴影尺度, num, 0~30, 默认5）、`strength`（校正强度%, num, 0~100, 默认100）、`position`（阴影位置, enum: center/left/right/top/bottom/unspecified, 默认 unspecified）

**USM 锐化节点（sharpen）**：
- 输入端口：`image`
- 输出端口：`image`
- 参数：`amount`（数量%, num, 1~500, 默认100）、`radiusPercent`（半径%, num, 0.01~10, 默认0.1）、`threshold`（阈值, int, 0~255, 默认0）

**曲线节点（curve）**：
- 输入端口：`image`
- 输出端口：`image`
- 参数：`points`（曲线点, json, 默认 `[{"x":0,"y":0},{"x":255,"y":255}]`）
- 点击节点打开的浮窗中应包含一个曲线编辑器（复用现有 `src/ui/curve.js` 的绘制逻辑），用户可视化地拖拽曲线点，而不是手动编辑 JSON。浮窗中的曲线编辑器修改后，自动更新节点的 `points` 参数。

**自定义脚本节点**：
- 输入端口：`image`
- 输出端口：`image`
- 参数：由脚本的 `@param` 声明决定，动态生成。
- 卡片标题显示脚本的 `@name`。
- 添加此类型节点时，打开页面内脚本编辑器，提供包含注释头的脚本模板，也可导入 `.js` 文件替换草稿；保存后创建节点。脚本内容序列化存入流水线定义中（以便导出导入时自包含）。

**合成节点（composite）**：
- 左侧显示多个编号图像输入槽，每条连线占一个槽位；最下面保留空槽用于继续接线。
- 槽位从上到下就是叠放顺序，上方图层覆盖下方图层；拖动槽位可调整顺序。
- 一个图像输出端口 `image`，节点参数 `mode` 为共用混合模式。

### 2.3 连线

#### 2.3.1 创建连线

- 从一个端口（输出或输入均可）按住鼠标拖出一条线，拖到另一个兼容端口上松开，即创建连线。
- **拖拽过程中**：画一条从起始端口到当前鼠标位置的曲线（三次贝塞尔曲线，水平方向控制点偏移为两端水平距离的 0.4 倍，与 ComfyUI 类似）。曲线颜色跟随起始端口的颜色（黄色 = 图像，蓝色 = 参数）。
- **兼容性判定**：
  - 图像端口只能连图像端口。
  - 参数端口只能连参数端口，且数据类型要匹配（比如 int 参数不能连 enum 参数）。但如果类型兼容（int 可以连 number），允许连接。
  - 输入端口只能连输出端口（反之亦然），不能输入连输入。
  - 不能自己连自己（同一节点的输出连自己的输入）。
  - 不能形成环路。创建连线前检查：如果从 A 的输出连到 B 的输入，检查从 B 出发沿下游是否能到达 A，如果能则拒绝连接。
- **不兼容时**：拖拽过程中，不兼容的端口保持灰色不高亮；松开在不兼容端口上时，连线消失，无事发生。
- **兼容端口高亮**：拖拽过程中，所有兼容且未被占用的端口高亮放大。

#### 2.3.2 连线限制

- 一个**输入端口**只能接受**一条**连线（一个节点的某个输入只能来自一个源）。如果已有连线，新连线会替换旧连线。
- 一个**输出端口**可以连出**多条**连线（一个节点的输出可以分发给多个下游节点）。这就是分支的实现方式。

#### 2.3.3 删除连线

- 右键点击一条连线，弹出菜单"删除连线"。
- 或者：点击选中连线（连线变为高亮色），然后按 `Delete` 删除。
- 选中连线时连线变粗（3px → 5px）并变为高亮色。

#### 2.3.4 连线外观

- 三次贝塞尔曲线，线宽 3px，颜色跟随数据类型。
- 连线上有流动动画（沿曲线方向缓慢移动的虚线或小箭头），表示数据流方向。
- 节点绘制在连线上方。普通贝塞尔曲线不保证避开中间节点，本版本不做自动避障路径规划。

### 2.4 分支与合成

#### 2.4.1 分支

一个节点的输出端口连接到多个下游节点的输入端口，即实现分支。数据从该输出端口被"复制"分发给每个下游。

```
          ┌→ 降噪 → USM锐化 → 输出A
输入 → ──┤
          └→ 曲线 → 输出B
```

#### 2.4.2 合成

通过合成节点汇合多条分支。普通滤镜仍为单图输入，合成节点的编号槽位决定图层顺序。

```
        ┌→ 降噪 ─────→ 合成.第1层
输入 ──┤                ↓
        └→ 曲线 ─────→ 合成.第2层 → USM 锐化 → 输出
```

### 2.6 节点浮窗（参数编辑 + 预览）

#### 2.6.1 触发方式

单击一个节点的标题或参数区域（非拖拽），打开相对页面固定定位的浮窗面板，位置不随节点位置、画布平移或缩放改变。节点预览的点击不选择节点或打开浮窗；预览中拖动移动图片观察位置，滚轮缩放图片，事件不触发节点或画布操作。同一时刻只显示一个浮窗，点击另一个节点时前一个浮窗关闭。点击空白处或按 `Escape` 关闭浮窗。已有自定义脚本节点仍打开脚本编辑器，其中包含节点参数与预览。自带滤镜浮窗提供“编辑脚本”，载入默认脚本的独立编辑草稿；保存实际修改后转为自定义脚本，节点名称不变。

#### 2.6.2 浮窗内容

- **标题**：节点类型名 + 节点实例名称。
- **布局**：横屏左侧参数、右侧预览；竖屏上方参数、下方预览。标题和关闭按钮固定在窗口顶部，参数区独立滚动。窗口尺寸受页面可用空间约束；预览视窗尺寸变化时重新绘制并更新观察区域。
- **预览区**（如果信息侧栏已指定预览图片）：
  - 并排显示该节点输入与输出，两个视窗保持方形，按可用宽高等比缩小。拖动和缩放同步，参数变化后更新结果区域。
  - 同侧栏图片视窗共享图片缩放与中心；打开浮窗后只按浮窗视窗尺寸计算观察区域，预览上限为 1600×1600 原始像素。输入、结果视窗共用预览状态判定：只有超限时提示用户放大；有效区域尚无结果时显示“等待计算”，正在执行的节点显示“计算中”；无法计算时显示具体原因。
- **参数区**：列出该节点的所有参数，每个参数一行：
  - 参数名标签。
  - 输入控件（slider + number 联动、下拉框、复选框等，根据参数类型生成）。
  - 右侧一个"暴露"按钮（图标：向上箭头或链接图标），点击后将该参数暴露到输入节点，生成变量。如果已暴露，按钮变为"取消暴露"（高亮状态），点击取消。
- **曲线节点**的浮窗比较特殊：参数区替换为一个完整的曲线编辑器画布（复用现有 `src/ui/curve.js` 的 canvas 绘制 + 交互逻辑），用户可视化地拖拽曲线点，而不是手动编辑 JSON。浮窗中的曲线编辑器修改后，自动更新节点的 `points` 参数。

#### 2.6.3 参数修改的即时效果

- 修改参数后，该节点及其所有下游节点的预览缓存失效。
- 浮窗打开期间只计算当前目标及其必要上游，浮窗内的预览自动刷新；画布节点预览保留已有图像，关闭浮窗后按“编辑器预览”开关恢复计算与刷新。
- 刷新有 200ms 的 debounce，避免拖拽 slider 时过于频繁地触发滤镜运算。

### 2.7 变量暴露机制

#### 2.7.1 暴露方式一：浮窗中点击"暴露"按钮

1. 用户在某个节点的浮窗中，点击某个参数旁边的"暴露"按钮。
2. 系统自动：
   a. 生成一个内部 `variableId`（UUID）。
   b. 在输入节点上创建一个新的输出端口，端口名 = `节点名.参数名`（如"降噪.匹配容差"）。
   c. 创建一条连线，从输入节点的新端口连到该节点的参数输入端口。
   d. 变量的默认值 = 该参数当前在节点中设置的值。
3. 暴露后，该参数的输入控件旁边显示一个蓝色链接图标，表示它被外部变量控制。在节点编辑器内，用户仍然可以修改这个值——修改的是**默认值**。

#### 2.7.2 暴露方式二：拖拽连线快捷操作

1. 在节点浮窗的参数区，每个参数左侧有一个小的"拖拽手柄"（参数端口）。
2. 用户从这个手柄拖出一条线，连到输入节点的卡片上任意位置（不需要精确对准某个端口）。
3. 松开后，自动执行与"暴露"按钮相同的操作：生成变量、创建端口、创建连线。

#### 2.7.3 取消暴露

- 在浮窗中点击已高亮的"暴露"按钮，或删除从输入节点到该参数的连线，即取消暴露。
- 取消后：输入节点上对应的端口和变量被移除，连线删除。参数恢复为节点本地控制，值保持取消暴露前的默认值不变。

#### 2.7.4 变量在输入节点卡片上的显示

输入节点的卡片内容区列出所有已暴露的变量：

```
┌──────────────────────────────────┐
│  [蓝] 输入                       │
├──────────────────────────────────┤
│  image ────────────────────── ○  │  ← 固定的图像输出端口
│  降噪.匹配容差 = 25 ────────  ○  │  ← 暴露的变量，显示默认值
│  曲线.曲线点 = [...] ───────  ○  │
└──────────────────────────────────┘
```

变量的显示名（`节点名.参数名`）可以由用户双击重命名。重命名只影响显示名，不影响内部 `variableId` 和参数映射。

### 2.8 信息侧栏

固定悬浮在画布右侧，不随画布平移/缩放而移动。宽度约 280px。

#### 2.8.1 内容

从上到下：

1. **缩放控制**
   - 显示当前缩放百分比，可直接编辑输入框修改。
   - "适应画布"按钮：自动调整缩放和平移，让所有节点在视口内可见。
   - "100%"按钮：重置到 100% 缩放。

2. **预览图片选择**
   - 选图控件位于“编辑器预览”开关下方，仅在勾选时显示；关闭时隐藏手动选图按钮、图片集选择器和图片选择器，保留已选图片及选图设置。
   - 一个"选择预览图片"按钮，点击弹出文件选择器（`accept="image/*"`，单张）。

### 2.9 合法性判定

流水线合法的充要条件：

1. 存在**至少 1 个输入节点**（输入节点不可删除，所以始终满足）。
2. 存在**至少 1 个输出节点**。
3. **每个输出节点**都能从输入节点经过一系列连线到达（即从输入到该输出存在通路）。

不合法时的提示示例：
- "缺少输出节点"
- "输出节点 #2 未连接到输入"
- "存在断开的节点：USM 锐化"

不合法的流水线仍然可以编辑和保存，只是在任务层无法执行（"开始"按钮灰色，tooltip 显示原因）。

### 2.10 编辑器预览的计算逻辑

1. 用户选择预览图，解码为 ImageData，通过图片视窗缩放和移动选择观察区域；卡片与侧栏均为方形视窗，普通预览使用两者的最大可见区域，上限为 800×800 原始像素，打开节点浮窗后只按浮窗方形视窗尺寸计算观察区域，上限为 1600×1600。卡片不会被识别成浮窗而改变上限。超限时停止计算并显示当前上限及放大图片的提示；浮窗结果区直接显示无法预览的原因。计算失败时在预览状态和浮窗结果区显示错误，并弹出提示。
2. 对流水线图做拓扑排序。
3. 从输入节点开始，输入节点的预览 = 当前可见原始像素裁切。所有节点采用同一观察区域。
4. 按拓扑序依次对每个节点执行滤镜（使用 `ScreenFilters.start()`），输入为上游节点的输出。
5. 将每个节点的输出缓存，绘制到该节点卡片底部的 `<canvas>` 上。
   每个节点完成后只更新自己的卡片；浮窗打开期间只更新浮窗，暂停画布节点预览。页面可见时等待浏览器绘制，再通过 MessageChannel 继续下一节点，避免重复重画整个图或快速节点在同一帧显示。页面隐藏时立即解除已有绘制等待，后续节点直接继续计算；取消计算同样解除等待并清理动画帧、消息端口及监听器。全部命中缓存时仍在执行结束后刷新当前预览。
6. **缓存失效策略**：修改某个节点的参数时，该节点及其所有下游节点的缓存失效并重新计算。修改连线时，受影响的节点及其下游缓存失效。
7. 计算是异步的（Worker），进行中节点的画布及参数面板预览视窗上沿显示 3 像素细进度条，按该节点实际进度更新；完成、取消或失败后隐藏。进度更新不重绘未变化的图片。
8. 参数或脚本修改仅失效受影响节点及沿输出连线可达的下游；连线修改从接收节点开始失效，删除节点前记录其下游。移动节点、修改名称不重算图片。图片视窗变化只清除对应视图的观察区域缓存，取消过时计算。编辑器预览关闭时仍可计算当前浮窗节点及其上游。
9. 局部预览不调用输出保存。依赖整页尺寸或全页阴影检测的滤镜、裁切边界附近的结果可能与整图任务不同，最终结果以整图任务为准。

## 3. 执行引擎（任务运行时）

### 3.1 拓扑排序

任务开始执行前，对流水线图做拓扑排序（Kahn 算法或 DFS），得到节点执行顺序。如果图不合法（没有从输入到输出的通路），拒绝执行。

### 3.2 单图执行流程

对于图片集中的每张图片：

1. 将图片解码为 `{ data: Uint8ClampedArray, width, height }` 格式的 ImageData。
2. 初始化一个 Map<nodeId, ImageData>，将输入节点映射到当前图片。
3. 按拓扑序遍历每个处理节点：
   a. 取其上游节点的输出作为输入（通过 edge 的 from/to 查找）。
   b. 汇总该节点的参数：如果某个参数被暴露为变量，使用任务层的用户填写值；否则使用节点内的默认值。
   c. 调用 `ScreenFilters.start(filterId, inputImage, params)` 执行滤镜。
   d. 等待结果，存入 Map。
4. 到达输出节点时，按输出设置保存结果。
5. 如果图中有分支（一个输出连多个下游），每个分支独立执行（同一个输入被复制到多个下游）。

### 3.3 进度报告

- 任务级进度：已处理图片数 / 总图片数。
- 单图内进度：当前正在执行的节点名 + 该节点滤镜的 progress（由 `FilterAPI.progress()` 报告）。
- 进度信息实时更新到任务卡片上（即使卡片处于收起状态，进度条也可见）。

### 3.4 错误处理

- 单张图片处理失败（滤镜报错）时：记录错误信息，跳过该图片，继续处理下一张。
- 全部完成后，如果有跳过的图片，任务状态为 `completed`（不是 `error`），但卡片上显示"已完成，N 张失败"，可展开查看失败的文件名和错误信息。
- 单图中的 GPU 获取/执行失败同样记录到该图错误列表。任务调度自身发生无法继续的错误时状态为 `error`。任务开始前缺少配置、文件或写入授权时显示问题，不消耗进度。

| `curve` | `curve` | `src/filters/tone.js` | cpu | 曲线 |

| `maximum` | `maximum` | `src/filters/basic-filters.js` | gpu | 最大值；半径至 500，保留方形／圆度 |
| `minimum` | `minimum` | `src/filters/basic-filters.js` | gpu | 最小值；半径至 500，保留方形／圆度 |

### 6.1 降噪 GPU/CPU fallback

Banner 右上角的主题控件左侧以 10px 字号显示 GPU 信息。页面启动时按自带 GPU 滤镜相同的 `high-performance` 偏好查询适配器，优先显示描述，否则显示浏览器公开的厂商、架构及设备 ID；未公开型号或 WebGPU 不可用时显示对应状态。长文本省略，悬停显示设置提示及完整适配器信息。点击复制 `chrome://flags/#force-high-performance-gpu`，成功后弹出 toast，提示用户粘贴到 Chrome 地址栏，将 Force High Performance GPU 设为 Enabled 并重启 Chrome。

- 系统启动时检测 `navigator.gpu` 是否可用。
- 如果 WebGPU 可用，降噪节点使用 `denoise`（GPU 版）。
- 如果 WebGPU 不可用，降噪节点自动 fallback 到 `denoise-cpu`（CPU 版），参数定义完全一致，用户无感。
- 在节点卡片标题栏右侧显示一个小标签 `GPU` 或 `CPU` 指示当前使用的实现。
- USM 锐化同理：如果 WebGPU 不可用，整个锐化节点变为不可用状态（因为没有 CPU fallback），卡片标题栏显示"需要 WebGPU"的警告。

降噪、USM 锐化、表面模糊、最大值、最小值和查找边缘共用 GPU 批次调度器，每个计算阶段最多两批在途，按实际完成批次汇报进度，通过 MessageChannel 让出 Worker 事件循环处理取消，再补交下一批。多遍滤镜等当前阶段结束后再进入下一阶段；降噪的亮度预处理与匹配按 GPU 队列顺序执行，不在两者之间额外等待主机通知。

初始批量按核工作量设置，后续按完成通知的吞吐估算约 16 ms 的批次规模；每次调整最多增至两倍或减至一半。降噪批量范围为 64–16384 像素，USM 为 64–65536，常用四种滤镜为 1–65536。完成通知包含排队、计算与调度开销，16 ms 是调优目标，不保证单批 GPU 耗时。每批参数上传与 dispatch 按同一队列顺序提交，后续参数不会覆盖前一批使用的值。既有自定义脚本副本保留其原有源码及提交方式。

GPU 降噪在每个 64 线程工作组中处理 8 个像素，每像素由 8 条线程按候选位置交错分担搜索。参考图块存于组内共享数组，容量按当前半径生成；最大半径时组内共享存储共 15904 字节。各线程保留自身最好的 12 个候选，再由像素的首线程合并 8 份排序列表，按距离及原始逐行候选顺序选出全局最好的 12 个；距离计算顺序、透明度规则、接受阈值及加权计算保留。尾批和透明像素的线程同样参与工作组屏障，在最后一次同步后才允许退出。每批进度仍按输出像素计数，工作组数量按每组 8 像素换算。CPU 对照实现保持原有顺序算法。

## 7. 自定义脚本滤镜生命周期

### 7.1 导入

1. 用户在节点编辑器右键菜单中选择"自定义脚本滤镜…"，打开页面内脚本编辑器，提供在注册工厂开头声明 `ScreenFilter` 注释头的模板。
2. 用户可直接编辑，或通过“导入 JS”读取文件全文替换草稿；解析元数据后更新左侧表单。打开及导入脚本时自动定位注释头。
3. 如果解析失败（缺少 `==ScreenFilter==` 头部、缺少 `@id` 或 `@name`），显示错误，不创建节点。保存时校验表单、注释头及 JavaScript 语法。
4. 脚本声明的 `@id` 保留在元数据；实际注册时使用独立运行时 ID，不覆盖内置滤镜。完整源码相同则复用；源码不同的同名脚本分别执行，避免导入另一条流水线后误用脚本版本。
5. 保存后，在右键位置创建一个 `custom` 类型节点，节点的 `scriptSource` 存储完整 JS 源码，`scriptMeta` 存储解析出的 `{ id, name, device, params }` 等元数据。

### 7.2 序列化与恢复

- 流水线保存到 localStorage 时，自定义脚本节点的 `scriptSource` 和 `scriptMeta` 一起序列化存入。
- 恢复流水线时，按完整源码查找运行时注册。相同源码复用注册，不同源码用新的运行时 ID。节点持久化数据不依赖临时运行时 ID。
- 流水线导出为 JSON 时，`scriptSource` 也包含在内，导入方无需额外拥有脚本文件。

### 7.3 脚本更新

- 自定义脚本节点单击后打开页面内脚本编辑器，支持源码及注释头参数定义双向编辑；可导入 JS 替换编辑草稿。保存更新当前节点，取消或关闭丢弃草稿。
- 表单修改名称、ID、入参后即时更新 `@id`、`@name`、`@param`；保留注释头的其他声明及说明，包括 `@device`、`@input`、`@geometry`、`@option` 和 `@output`。某个默认值暂时超出范围时，其他定义继续同步，保存时校验整份表单。
- 自带滤镜浮窗提供“编辑脚本”按钮，载入当前实际使用的完整默认实现，包括共享 GPU 执行函数。仅当保存的源码与原脚本不同，才把该节点改为 `custom`，保存独立源码及元数据；节点名称、ID、位置和图像连接不变。修改脚本名称不会重命名现有节点。
- 自带滤镜注册生成的独立脚本在注册工厂开头放置唯一 `ScreenFilter` 注释头，共享函数排在其后，内部原工厂不重复放置头部；已有自定义源码保持原样，打开时定位其头部。
- 未变化的参数保留当前值；类型或声明默认值改变时采用新默认值；删除、改名或改类型的参数移除旧值连线。未修改就保存不转换节点。
- 常用 GPU 滤镜每个计算阶段分批提交、最多两批在途，完成后汇报实际进度并通过 MessageChannel 让出事件循环，取消时销毁设备；批量按完成通知的吞吐调节，规则见 §6.1。表面模糊在圆盘邻域内逐 RGB 通道排除与中心差值超过阈值的像素，对接受的像素按透明度加权平均，保留中心透明度；半径执行时四舍五入到整数，初始批量按二维邻域工作量设置。方形最大值／最小值使用两遍计算；圆度模式使用圆盘邻域及相邻整数半径结果插值。方形半径为 1–500 整数，圆度半径为 0.2–500、步长 0.1；默认方形、半径 1。参数形式参照 PS，内部算法不保证与 PS 逐像素一致。
- 保存及导入的旧 `gaussian-blur` 节点通过 `Store.migrateSurfaceBlur(graph)` 统一转换为 `surface-blur`，原半径取整并限制在 1–100，补上默认阈值 15。节点与变量 ID、连线及自定义名称保留；原默认节点名及默认半径变量名改为表面模糊，半径变量更新范围和默认值，已保存任务的半径覆盖值同步换算。任务执行键随图变化，已有进度需清空后重跑；自定义脚本副本不替换。

## 8. 曲线编辑器复用方案

### 8.1 现有 src/ui/curve.js 分析

重构前 `src/ui/curve.js` 导出 `ScreenCurve.create(onChange)` 并绑定固定 DOM ID；此绑定已替换为下述容器接口。

### 8.2 重构方案

已将 `src/ui/curve.js` 改为可实例化版本，可挂载到任意容器：

```js
// 改造后的 API
ScreenCurve.create(container, {
  onChange: (points) => { /* 曲线点变化回调 */ },
  initialPoints: [{x:0,y:0},{x:255,y:255}],  // 初始曲线点
  width: 280,   // canvas 宽度（px）
  height: 280,  // canvas 高度（px）
})
// 返回 { points(), setPoints(arr), reset(), destroy() }
```

改造要点：
- 不再 `getElementById`，改为在传入的 `container` 内动态创建 `<canvas>`、输入框、删除按钮等元素。
- 返回的对象增加 `destroy()` 方法，用于从 DOM 移除创建的元素并解绑事件监听器（浮窗关闭时调用）。
- 返回的对象增加 `setPoints(arr)` 方法，用于从外部设置曲线点（加载已有节点参数时使用）。
- `onChange` 回调参数改为直接传入 `points` 数组，调用方不需要再通过 `.points()` 取值。

### 8.3 使用场景

- **节点浮窗**（§2.6）：打开曲线节点的浮窗时，在浮窗的参数区创建一个曲线编辑器实例，传入当前节点的 `points` 参数。用户拖拽曲线点后，`onChange` 更新节点参数并触发预览刷新。浮窗关闭时调用 `destroy()` 清理。
- **任务参数区**（§1.3.2）：如果曲线的 `points` 参数被暴露为变量，任务层的参数编辑区也需要一个曲线编辑器。同样创建一个实例，传入用户填写的 `points` 值。

## 9. 边界情况与约束

### 9.1 localStorage 容量

- localStorage 通常有 5~10 MB 限制。流水线定义和任务定义一般很小（几十 KB），但自定义脚本节点的 `scriptSource` 可能较大。
- 如果 `localStorage.setItem()` 抛出 `QuotaExceededError`，在 UI 顶部弹出 toast 提示"存储空间不足，请删除不需要的流水线或任务"。不做自动清理。

### 9.2 同时打开多个标签页

- 不做跨标签页同步。如果用户在多个标签页中同时编辑，后保存的会覆盖先保存的。
- 可以监听 `window.onstorage` 事件，在检测到其他标签页修改了数据时，弹出 toast 提示"数据已在其他页面被修改，请刷新"。

### 9.3 大图片处理

- 单张图片的 ImageData 可能很大（比如 6000x4000 RGBA = 96 MB）。
- 每个任务按顺序读取源图片，一张完成后再读下一张；处理期间可能有该图的多个中间节点结果，用于分支与合成。不会把整个图片集提前解码进内存。
- 分支场景：一个节点的输出被多个下游共享时，共享同一份 ImageData 引用（只读）。只有当下游节点修改它时才产生新的 copy（滤镜本身会 `new Uint8ClampedArray` 创建输出，不会修改输入）。

### 9.4 GPU 设备丢失

- 如果 WebGPU 设备在处理过程中丢失（`device.lost`），当前滤镜会抛错。
- 错误由执行引擎捕获，记录该图片为失败，跳过继续处理下一张（下一张会尝试重新创建 GPU 设备）。

### 9.5 File System Access API 兼容性

- 通过检测实际文件访问接口决定是否能写入，目标运行环境是 Chrome / Edge + localhost。
- 无写入能力时明确提示，用户仍可编辑流水线与预览。输出模式不会偷偷转换为下载。
- JSON 序列化不能保存文件/目录句柄；`src/io/asset-locations.js` 使用 IndexedDB 保存图片集来源位置句柄，用于刷新后的选择器定位。刷新后仍需选择来源目录以加载图片；输出目录句柄不持久化，需要重新授权。

### 9.6 流水线引用完整性

- 删除流水线时，引用该流水线的任务不会被自动删除，但其 `pipelineId` 变为无效引用。
- 任务卡片检测到 `pipelineId` 指向不存在的流水线时，显示警告"所选流水线已被删除"，"开始"按钮灰色不可用，用户需要重新选择流水线。
- 删除图片集同理：引用该图片集的任务显示警告，需要重新选择。

### 9.7 空流水线与空图片集

- 流水线可以只有输入节点没有输出节点（不合法但可保存编辑）。
- 图片集可以文件列表为空（允许存在，但引用它的任务无法运行）。
- 任务可以不选图片集或不选流水线（`imageSetId` / `pipelineId` 为 `null`），此时"开始"按钮灰色，tooltip 提示缺少的配置。

- `src/core/engine.js`：`Engine.execute(graph, source, options)` 返回 `Map<nodeId, image>`。`options` 包含任务覆盖值 values、单个 target 或多个 targets、缓存 cache、进度和节点结果回调、AbortSignal。等待 `onNode` 返回的 Promise，允许调用方在节点之间完成绘制。默认执行所有输出的必要祖先，预览可指定处理目标。该方法不保存文件。

| 流水线图、节点名称/位置/本地参数、连线、输入变量及类型 | 是 | 是 |
| 自定义脚本完整源码 | 是 | 是 |
| 画布位置/缩放 | 是，流水线 graph.view | 是 |
| 预览开关、图片视窗位置/缩放、图片集及图片选择、预览图名称 | 是，独立编辑器状态 | 是 |
| 预览图片 File 副本 | 否，单独保存到 IndexedDB | 是 |
| 解码后的预览图像、滤镜中间输出、Worker、结果缓存 | 否 | 是 |
| 输出目录显示名称 | 是 | 是 |
| 输出目录句柄及写入权限 | 否 | 是 |
| 任务选择、覆盖参数、状态、已完成数、错误、耗时、执行签名 | 是 | 是 |

任务只存显式覆盖值；未覆盖时读取流水线默认值，不将变量 ID 当作用户标签。任务中修改参数不会改流水线默认值。删除连线取消暴露时，当前默认值复制回节点本地参数。输出目录遵循同一规则，选目录时生成独立引用键，避免后续选择改变运行中的任务快照所引用的句柄。

### 11.3 生命周期与任务检查点

1. 新任务开始前校验引用、图合法性、图片授权、目录授权和原地保存权限。
2. 文件选择和授权期间属于准备状态，阻止该任务重复启动及修改其输入；取消后不改变进度。
3. 正式执行前复制流水线图、参数与图片列表作为本次执行快照。正在编辑的流水线不会改变当前已开始的执行。
4. 每张图片全部处理和各输出保存结束后才递增已完成数，持久化检查点与错误。
5. 暂停请求在当前图片保存结束后兑现；最后一张结束时使用 completed。
6. 清空进度保留任务名称、选择和覆盖值；不删除图片文件。
7. 暂停/刷新后恢复时核对执行签名。处理节点、处理参数、连线、变量默认值或图片列表改变时，提示先清空进度；画布位置及缩放不计入执行签名。
8. 使用原地保存时，清空进度再次运行会对已覆盖的文件再次处理，这是原地保存的实际语义。

### 11.4 预览缓存

- 输入图和当前裁切作为预览数据源，缓存 key 为节点 ID。画布与浮窗分别保留各自的缓存及对应原图、观察区域；开关或切换浮窗不清空画布缓存，回到相同原图和区域时复用结果。
- 参数变化失效该节点及所有下游；一个外部变量连接多个节点时，失效所有使用它的节点及各自下游。
- 输入节点浮窗显示原始输入及流水线首个输入路径完整的输出节点结果；关闭编辑器预览时也计算该输出的必要上游。输入变量编辑与节点参数编辑共用 `Graph.setVariable`，失效所有使用该变量的节点及其下游，保留其他分支缓存。
- 改变视窗或图片时清除对应视图的观察区域缓存。改变连线仅清除接收节点及其连通下游，删除节点前记录受影响下游；参数及脚本修改遵循同一失效范围，共享输入默认值的修改还会失效使用该变量的节点及下游。移动节点、修改名称不失效图像缓存。AbortSignal 取消过时滤镜计算。
- 编辑器预览开启：计算已有完整输入路径的节点；草稿中断开的节点只显示未连接，不阻止其他完整分支预览。
- 普通画布预览先计算输入完整的输出节点及其必要上游，逐节点显示结果后再计算未接入这些输出的草稿分支，避免慢草稿阻塞输出路径。两组共用当前视图缓存；各组单独按依赖中的偏移／合成节点选择普通或空间预览执行器。无输入完整的输出节点时，仍计算输入完整的草稿节点。浮窗始终只执行当前目标及其必要上游。
- 编辑器预览关闭：打开浮窗后仍计算目标节点及其必要上游，不自动执行文件输出。
- 卡片及浮窗共用状态提示判定：超限显示当前上限及放大提示，有效区域无缓存显示“等待计算”，当前执行节点显示“计算中”，计算失败显示错误。未完成计算不再提示放大；整图试跑期间无结果的预览显示暂停原因。800×800／1600×1600 上限保持不变。
- 曲线、数字滑块等控件不会因每次参数更新而重建浮窗，拖动可以连续进行。
- 卡片、侧栏及浮窗复用同一图片视窗绘制和交互逻辑。卡片重绘保留已挂载的预览元素；关闭预览或删除节点时解除其挂载及尺寸观察。预览的点击、拖动和滚轮不冒泡到节点或画布。节点画布缩放不改变图片缩放，鼠标坐标换算到预览局部像素。所有图片视窗保持方形，Canvas 显示尺寸与绘制尺寸一致，避免独立约束宽高造成拉伸。
- 浮窗打开期间只执行当前目标及其必要上游，节点结果回调只重画浮窗；画布节点预览保留已有图像，关闭浮窗后恢复并复用未失效结果。普通预览回调只重画完成节点对应的视窗，不重画其他视窗；结果、状态和图片视窗未变化时跳过重复绘制，尺寸变化时只重画尺寸变化的视窗。页面可见时等待一次动画帧后的 MessageChannel 任务再继续，确保逐节点提交可见结果；页面隐藏或计算取消时解除已有绘制等待，页面隐藏期间直接继续计算。全部命中缓存时在执行结束后同步预览状态。
- 重新进入编辑器或刷新后恢复对应流水线的预览图片副本、预览开关和图片视窗设置。预览操作不调用流水线更新，不改变其最后编辑时间；旧版只保存了图片名称时仍需重新选择一次图片。
- 预览为局部裁切计算；去阴影的全页检测、USM 的整图百分比半径等上下文相关参数最终以任务整图结果为准。
- 试跑按钮位于预览图片选择区下方；要求已选择图片且流水线合法。整图执行点击时的图和默认参数快照，不受局部裁切大小限制。试跑使用独立缓存和 AbortSignal，期间暂停局部预览，离开编辑器取消执行。
- 试跑总进度 = 所有实际执行节点的 0–1 进度累积 / 实际执行节点数 × 100，包含输入、输出及其必要祖先；未参与输出的草稿节点不计入。界面同时显示当前节点名及其百分比。
- 试跑启动及节点间使用与预览相同的绘制等待，页面隐藏时继续处理；首页批处理不等待界面绘制。应用不主动因窗口最小化暂停计算，但不保证浏览器冻结页面或系统休眠时仍继续处理。
- 试跑完成后每个输出节点下载一份图片，应用该节点的颜色模式。原地保存节点下载 PNG，目录保存节点使用所选格式及质量；单输出命名为“原图名_试跑.扩展名”，多输出增加序号。试跑不覆盖原图、不写入输出目录，不修改任务进度。

### 11.5 当前验证范围

2026-10-14 偏移：新增偏移节点，支持像素／百分比、正负水平和垂直值；百分比按上游整图宽高计算并取整，单位切换沿用数字。正向扩展画布保留内容，负向越过原点的像素裁切，保留原宽高。通过 Worker 执行，参数可暴露到输入，默认脚本可编辑；`src/core/spatial-preview.js` 为偏移分支反向请求对应坐标的裁切，并复用 `Engine.runNode` 执行，节点显示缓存与临时区域缓存分开。按项目规则仅做语法静态检查，未运行自动化验收。

2026-10-14 缩放：`src/filters/resize.js` 自带滤镜及尺寸控件支持缩小和放大，百分比可超过 100%，像素尺寸可超过上游原图，输入不设上限。菜单及脚本名称为“缩放”；已保存及导入的自带节点旧默认名“缩图”和对应默认输入变量名同步更新，用户自定义名称保留。宽高支持百分比／像素单位、比例锁定及独立编辑。锁定且单位为像素时，当前编辑的固定轴高亮，另一边只读显示“根据计算”，聚焦另一边切换固定轴；锁定且单位为百分比时，两个输入框都可编辑且数值同步；解锁后两边均独立编辑。仅使用内置两次立方自动重采样，不展示算法选择。参数为带 `editor: "resize"` 的 JSON 尺寸对象，统一用于节点浮窗、输入暴露和任务覆盖。预览裁切携带整图尺寸及位置，缩放换算这些字段，执行引擎为后续像素滤镜及合并节点保留它们；显示时根据结果整图尺寸将宽高和裁切位置换算回原图坐标，使输入与结果显示同一观察区域，同步拖动与缩放。批处理及试跑使用上游整图尺寸，输出编码沿用现有流程。项目算法不保证与 PS 逐像素一致。
